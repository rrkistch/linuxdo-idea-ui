### 1.1 本轮交付目标

完成下述 T00—T10 中的必做要求，并提供可安装的单文件脚本、可重复的测试方法及如实填写的验收结果。可选增强不能挤占必做修复。

验收重点不是“截图里元素更多”，而是：

- 外壳、线程、代码面板与当前内容有明确对应关系。
- 关键按钮真的工作，切页、恢复、失败重试不会产生状态错配。
- 正文、图片、表格、代码和操作入口仍然可读、可用。
- 用户能辨别实际发布位置，脚本不会把装饰内容作为真实内容发送。

### 1.2 明确不做

不重写为 React/Vue/Electron，不引入后端或登录系统，不要求用户先安装 Node 才能安装 userscript。不以持续滚动的假日志、永久运行中的假命令、随机重排代码作为默认效果。不修改浏览器地址栏或声称页面能隐藏浏览器历史、站点来源、网络记录。

品牌仅作非官方外观参考，保留项目原有许可、作者署名与非官方说明。本文没有给出“最新 Codex 官方像素规范”；尺寸建议属于待校准的设计初值。

## 3. 不可破坏的约束

### 3.1 内容、身份和真实操作

正文、标题、链接、代码、引用和附件必须保留原始数据。外观别名只能存在于展示层，不得覆盖 `topic.title`、分类数据、发送目标、引用原文或链接地址。项目风格标签不能把真实发帖伪装成不会发布的本地命令；编辑器发送前必须能看到真实目标分类或回复对象。

装饰节点与真实内容分离，禁止混入正文复制、引用、剪贴板、发送 payload、搜索索引和阅读统计。不得增加外部 AI 请求或把论坛内容发送到第三方服务。

### 3.2 用户脚本与站点兼容

保留单文件直接安装路径，优先沿用当前 `@grant none` 和原生站点 API/桥接方式。不得为视觉需求扩大站点匹配范围、增加跨域特权或引入运行时 CDN 依赖。开发测试依赖可以存在，但不应成为用户安装脚本的前置条件。

不改写其他主题的 DOM、class、存储和事件；不把通用选择器扩展到登录页、验证页、原生编辑器或未支持路由。已有失效路径可以修复，但不得借机重构其他皮肤。

### 3.3 工作区、测试和发布

保留用户未提交的改动，禁止 `reset --hard`、强推或大规模全文件格式化。没有额外授权时，只在本地工作区修改、生成补丁与交付说明；不得推送远程、合并 PR、发布 Release 或改仓库可见性。

自动化优先使用模拟数据和拦截请求。禁止为了验收而在用户真实账号上自动发帖、点赞、收藏、投票、上传附件或伪造阅读量。需要真实写操作验证时，使用获准的测试环境；否则标记为待验收。

3. 为 E01—E12 逐项记录“仍存在 / 已修复 / 当前结构不同 / 需要浏览器验证”。当前实现已正确时，添加回归测试而不是重复替换。

**验收**：交付说明包含实际 HEAD、工作区保护方式、待修改范围、已存在能力和不能验证的环境条件；不得只引用本文而没有读取当前代码。

### T01 · 修复 `highlightCode()`，先保证源码不损坏

**目标**：字符串、URL、注释和特殊字符不丢失；高亮只能改变表现，不能改变原文。

**实施要求**

- 改为“读取原始文本 → 识别 token → 对每个 token 转义 → 一次生成 DOM/HTML”的流程。不要在已经包含 `<span>` 的 HTML 上再次运行数字、关键字等替换规则。
- 字符串识别必须先于字符串内部的注释判断。处理转义引号及支持范围内的跨行状态；对无法可靠识别的语法退化为转义后的纯文本，不能吞字或污染后续内容。
- 优先采用仓库已有可复用实现；没有则实现小而可测的扫描器。无需为五种语言自行编写完整编译器，也不允许以修复为由引入大型编辑器框架。
- 确认 TypeScript/JavaScript 的 URL/模板字符串、Python 字符串中的 `#`、支持语言中的跨行注释不会误处理。Rust 原始字符串等难以准确支持时，明确降级策略。
- 渲染只允许固定的高亮标签和 class；源码里的 `<`、`>`、`&`、引号和 HTML 片段不能成为可执行节点。
- 正文与右侧复制都读取原始代码文本，而不是包含行号和装饰的 `innerText`。

**最低测试输入**

```text
const msg = "hello";
const url = "https://example.com/a?x=1";
const quoted = "say \"hello\"";
const n = 42; // trailing comment
value = "# this is not a Python comment"
const markup = "<button>example</button>";
空行、制表符、中文注释、CRLF、多行注释、模板字符串
```

测试夹具应使用语言本身有效的转义，不能因为 Markdown 展示的反斜杠数量直接照抄错误输入。

**验收标准**

- 渲染后的代码内容节点 `textContent` 与约定换行归一化后的输入完全一致；行号不在比较范围内。
- 不残留 `\u0001`/`\u0002` 等内部占位符，不出现错误嵌套标签。
- URL 内部的 `//`、字符串内的 `#` 不被当作注释；真正的行尾注释仍正确识别。
- 未支持语法可没有高亮，但仍完整、可复制、不可执行。

### T02 · 图片预览不再撑开正文

**定位**：帖子图片 CSS、`openLightbox()`、`closeLightbox()` 及相应事件。

**实施要求**

- 移除 hover 时扩大 `max-width/max-height` 的正文布局变化。缩略图保持固定容器或稳定的受限比例，hover 只改变遮罩、边框和预览图标。
- 图片没有提前可用的宽高时，提供合理占位；加载完成和失败后都不要造成大范围跳动。emoji 单独处理，不套附件尺寸。
- 点击继续使用现有灯箱，保留缩放、拖动、原图入口、Esc 关闭等功能；不要重新做一套互不兼容的预览系统。
- 灯箱每次打开注册的窗口事件，关闭时必须释放或由单例统一管理；重复打开后不能叠加拖动响应。
- 补充点击背景关闭、键盘焦点返回、窄屏完整可见。新增触摸手势不是必做项，但不能让手机无法关闭图片。
- 不扩大视频、表格和长代码块到页面外；必要时让内容区域内部滚动。

**验收标准**

同一图片连续 hover 10 次，后续正文块的边界位置没有持续跳动；灯箱连续开关 20 次无重复事件、无残留遮罩；Esc 和关闭按钮均可用；图片错误、长图、emoji 和多图帖子保持可读。

### T03 · 统一原生回退、标题/favicon 与清理生命周期

**定位**：`bootstrap()`、`applyTheme()`、`makeFavicon()`、`loadTopic()`、`bindMainEvents()`，以及当前存在的回退/清理路径。

**原生模式**

- “在原生界面打开”构造同源目标 URL，携带明确的单页模式标记，例如 `cx_native=1`，保留原始路径、其他 query 和 hash。
- 在主题初始化前解析标记：命中时不得注入主题 CSS、替换标题/favicon、劫持 History、启动主题观察器或隐藏原生内容。
- 原生偏好不得写成影响全部标签页的全局开关。需要在当前标签页跨 SPA 导航保留时，使用有明确退出方式的标签页级状态；重新启用后能清掉该状态。
- 原生分支只可提供最小的“恢复 Codex 外观”入口，不能在后台继续运行整套主题。不要把该参数发送为业务 API 的筛选条件。

**页面外壳**

- 引入单一的外壳同步入口，集中管理标题、favicon、当前项目和模式。去掉 `loadTopic()` 等分散的品牌标题赋值。
- 默认可以使用 `当前线程 · Codex`；项目别名只有展示作用。需要减少标签标题的信息量时，提供本地固定工作区标题选项，而不是不可逆替换原始数据。
- 保存并能恢复原生标题/icon 来源。若用 title 观察器应限定在 title 节点、对自身写入去重，避免相互覆盖循环。
- 验证页、登录态异常页、其他主题激活、原生模式和不支持路由优先回退；不得为了维持品牌遮盖验证信息。
- Cloudflare 判定不得只依赖已被脚本改写的 title，应保留现有 DOM 检测和恢复机制。

**生命周期**

- 统一清理本脚本创建的主题 class、样式、浮层、计时器、观察器、请求和事件；保留用户草稿，不删除站点或其他脚本的数据。
- History 包装和全局事件幂等安装。清理时仅移除本脚本仍拥有的包装，不能覆盖后来由其他脚本接管的 History 实现。
- 关闭皮肤或回退原生后，后到的异步响应不能重新创建主题 UI。

**验收标准**

新开原生视图确实显示原站；刷新和站内导航符合约定的单页/单标签语义；恢复主题后不重复绑定。主题启用时标题/icon一致，关闭时恢复。验证页不被覆盖。原 URL 的 query/hash 和浏览器前进后退语义不被破坏。

### T04 · 修复请求归属、失败重试和分页串页风险

**定位**：`api()`、`loadList()`、`loadMoreList()`、`loadTopic()`、`loadOlderPosts()`、`loadNewerPosts()`、`jumpToSource()` 及其异步回调。

**状态要求**

区分“用户当前希望看到的路由”“本次请求目标”“已成功加载的数据”。不能在请求开始时设置了 ID，就把它当作可复用的成功缓存。

可采用以下概念，具体命名服从现有代码：

```text
routeKey       当前页面身份，包含实际需要的路径和查询条件
requestId      该请求域的单调递增版本
loadedKey      最近一次成功写入数据的身份
status         idle | loading | ready | error
controller     当前请求的取消句柄（如采用 AbortController）
```

**实施要求**

- 用户从 A 切到 B 时，A 的 `loading` 不能永久阻止 B 发起请求。采用请求版本号；可同时取消旧请求，但取消并不能代替结果归属检查。
- 每个异步写入点都校验当前页面身份和请求版本，包括 `catch`、`finally`、标题、代码面板、分类名回调、滚动恢复和分页追加。
- A 失败后，仍能在 A 页点击重试。冷却或缓存不能把明确的用户重试吞掉；自动重试与手动重试分开。
- 已有成功数据的刷新失败可保留旧数据并提示；首次加载失败显示明确重试入口。不要一直保留“加载中”。
- 列表筛选、查询参数和 API 缓存键保持一致，避免不同筛选共享错误缓存；本轮不随意改动站点 API 语义。
- 分页带上父线程/列表身份，返回后重新核验；引用跳转不能与当前分页互相覆盖。帖子按稳定 ID 去重，顺序按服务端流恢复。
- 明确处理跨过未加载区间的引用跳转，不得只扩张首尾索引却把中间缺口当作已加载。
- 保持 `api(path, extraHeaders)` 等现有调用兼容；加入 signal 时不要丢失阅读上报头、同源凭据或 CSRF 路径。

**验收标准**

在模拟响应可控的条件下，验证 A→B、A→B→A，分别使旧请求最后成功、最后失败；最终标题、正文、列表、面板均属于当前页面。旧请求的 `finally` 不会清除新请求的 loading。分页中切页无串页和重复楼层。首次失败后无需刷新即可成功重试。

### T05 · 收敛随机思考和工具装饰

**定位**：`buildThinking()`、`sprinkleActivity()`、`RUN_LINES`、`RUN_CMDS`、`THINK_*`，及装饰节点 CSS。

**默认模式**

- 默认关闭随机英文思考正文和随机工具活动。不再给大量回复前面插入默认展开的“Worked for”段落。
- 原帖内容不删减；保留真实引用、代码、附件等卡片。历史内容保持静态，只有真实加载状态显示活动反馈。
- 装饰与内容层分离。默认关闭后必须真正跳过生成和插入，而不只是用 CSS 藏住。

**保留一个可选演示模式即可**

- 只需一组固定、内部一致的示例场景，不扩建庞大素材库。项目、语言、文件、命令和状态由同一场景配置产生，刷新同一场景不随机变化。
- 演示活动默认收起、默认静止；配置界面和演示面板说明其为本地展示，不代表发生了真实命令、提交或 AI 调用。
- 不需要重连动画；若保留重试计数，则必须有合法范围和有界状态，禁止 `4/2`、无限运行和虚假的实际请求。
- 装饰节点设独立标记，展示模式切换可完整移除；引用、正文复制、发送和阅读统计不得选择到装饰。
- 非必要动画尊重减少动态效果的系统偏好；不引入假打字强制延迟真实内容出现。

**验收标准**

默认阅读十条回复，没有随机英文分析、跨语言假命令或永久转圈；开启再关闭演示模式后没有残留节点；复制/引用/发送 payload 与关闭演示时一致。

### T06 · 右侧从随机代码墙改为内容关联检查面板

**定位**：`genCodeLines()`、`renderCodePanel()`、`codePanelSeed()`、代码模式/语言菜单、正文代码块装饰。

#### A. 内容优先级

1. 当前线程已经加载的真实代码片段。
2. 没有代码时，展示已经加载的引用/附件入口或简洁空状态；允许保持关闭。
3. 只有显式开启演示模式，才显示固定示例文件和示例 diff。

没有真实数据时不凭空伪造仓库、源文件路径、改动计数或执行日志。也不要为了填充侧栏额外抓取整个长帖或所有分类。

#### B. 真实片段

- 从原帖内容的 `pre > code` 等实际代码节点提取纯文本，排除脚本生成的高亮包装、行号和演示内容。使用 `textContent`，不把原始 HTML 当代码执行。
- 以 `topicId + postId + blockIndex` 或等价稳定键标识片段。不同片段内容相同也应能定位回各自楼层，不因随意去重丢失来源。
- 文件名无真实依据时用 `snippet-01.ts` 等标签，并表明是片段；语言未知时显示纯文本，允许手动选择高亮语言。
- 正文代码块增加一个轻量的“侧栏查看”入口。点击后打开面板、选择对应片段，保留当前正文滚动和编辑草稿。
- 面板支持片段切换、复制、定位来源、关闭；复制不含行号、假路径和工具状态。
- 新一批回复加载后增量更新片段集合；当前选中仍存在时不抢选。切换线程清理旧线程片段。
- 只看过部分回复时，空状态写“已加载内容中暂无代码片段”，不声称整个话题没有代码。

#### C. diff 的真实含义

- 单个片段没有前后版本时，不生成随机 diff；隐藏或禁用该入口并解释没有可比较版本。
- 本轮演示模式至少保留一对固定 `before/after` 样例，用真实文本差异计算行变化。不要随机染色，更不要把示例标成用户仓库的实际修改。
- 两侧行号、hunk 范围、新增/删除数均从同一份差异数据派生；不能各自随机或硬编码。
- 对复杂比较有疑问时，先实现正确的单个变更块和标准上下文。手动选择任意两段代码比较属于可选增强。
- 若借用现有 diff 库，检查仓库依赖和许可并保持单文件运行；不得通过运行时 CDN 下载。

#### D. 更新策略

签名应包括实际内容版本、选择的片段/场景和模式，不再只依赖话题随机种子。保持无变更时不重绘，避免重置右侧滚动位置。尺寸变化只触发布局，不重新生成示例代码。

**验收标准**

有代码的帖子能正确列出已加载片段并回到来源；无代码的帖子不出现随机代码墙；切页、分页、关闭/再开面板不串内容。演示文件结构完整，diff 可由样例前后文本复算，行数和统计一致。

### T07 · 调整信息层级，移除虚构会话

**定位**：`sessionsForCat()`、`renderRailDynamic()`、`syncChrome()`、`trowHtml()`、`opTurnHtml()`、`agentTurnHtml()`。

**列表与详情**

- 列表优先展示真实线程标题、未读状态和时间。作者、摘要、回复数降低层级或放入可展开的详情，不做大面积标签堆叠。
- 作者、楼层、完整时间和阅读量进入轻量元信息入口；不能只依赖鼠标 hover，键盘焦点和触屏必须可访问。
- 回复/点赞/收藏/链接操作保留；无文字图标需提供明确可访问名称和选中状态。
- 默认继续保留首帖与回复的视觉区分。不能把其他真实用户一律改名为“AI”，也不能丢失作者来源和回复关系。
- 编辑器实际发送目标始终明确：显示真实分类或真实回复对象，展示别名不能覆盖这些信息。

**侧栏**

- 删除真实话题不足四条时用 `MOCK_SESSIONS` 补齐的逻辑。真实条目有几条就显示几条；空分组用安静的空状态或折叠状态。
- 分类可以采用项目式分组视觉，但每个会话条目必须能打开对应线程。分类入口和展开按钮职责分离。
- “最近”若继续取 `/latest.json`，标签应表达“最新”；只有基于用户实际访问记录时才叫“最近访问”。不得把两者混用。
- 展开状态、选中项按分类/话题 ID 保存，而不是按标题；异步更新不要擅自重新展开第一组。
- 限定最近访问记录数量，例如最多 30 个；不存整帖正文，提供清理入口。不要为了侧栏展示对全部分类逐个发请求。

**显示别名**

本轮仅需支持分类/项目的本地显示别名，或者在已有设置中提供等价能力。使用独立映射和统一的展示取值函数；重命名、清空、刷新后表现稳定。不修改原数据、不随机刷新别名、不影响真实 URL 与发帖分类。

真实话题标题的批量随机改名不在默认范围；手动逐话题别名属于可选增强。

**验收标准**

所有看起来是线程的侧栏条目都能进入对应线程；没有凑数条目。打开/折叠、改别名、返回列表后状态稳定。作者与真实发帖目标仍可查，显示模式不改变发送数据。

### T08 · 做实导航、可操作控件与键盘行为

**定位**：`ensureRail()`、`bindMainEvents()`、`bootstrap()`、侧栏与面板开关、编辑器事件。

**输入快捷键（P0）**

- 全局快捷键检查 `isContentEditable`、INPUT/TEXTAREA、相关可编辑祖先和输入法组合状态。
- `Ctrl/⌘+K` 不应在编辑器中强行打开全局搜索；不得破坏编辑区已有编辑快捷键。
- 如存在发送快捷键，也必须验证输入法候选确认不会误发送；保留现有明确发送按钮与草稿机制。
- 必要时通过 `composedPath()` 找到实际编辑目标，但不为此增加无关的 Shadow DOM 架构。

**导航与控件（P1）**

- 宽屏侧栏折叠真正改变布局并可恢复；窄屏采用抽屉语义，不混成同一个失效的 class。
- 后退/前进调用符合当前站内导航机制的动作。浏览器无法可靠得知整个 forward stack 时，不得编造可用状态；可仅对脚本已知的站内导航记录提供准确禁用状态。
- “我的草稿”若仅调用新话题编辑器，应改名为“新线程/新话题”；已有真实草稿入口能可靠复用时再接入，不能凭空猜一个路由。
- 无功能的 AI 机器人、更多、放大、新建标签等装饰控件，隐藏或改为真实且必要的功能，不增加新的空按钮。
- 优先使用真实 `button`/`a`，补全 type、aria-label、aria-expanded、disabled、可见焦点。展开/折叠可用键盘，菜单关闭后焦点返回触发者。
- Esc 按层级关闭最上层弹窗，不连带清空草稿或关闭整个页面。只有真正模态弹窗才限制焦点范围。

**验收标准**

非编辑状态快捷键可用；contenteditable、输入法候选期间不被抢走；任何“能点”的控件都实现标示功能或明确禁用。后退/前进不串页，侧栏折叠后仍有恢复入口，Tab 可到达关键动作。

### T09 · 统一布局、浮层、尺寸与偏好

**定位**：`RAW_CSS`、宽度恢复/拖拽逻辑、主题同步、菜单/通知/灯箱等浮层。

#### A. 布局与视觉取向

沿用三栏骨架：左侧项目/线程导航，中间阅读与编辑，右侧按需检查。不要额外堆叠第二套工具栏或大面积品牌 Logo。

以下只作试排初值，不是官方规格：

| 场景 | 初始策略 |
|---|---|
| 约 1440px 宽桌面 | 左栏约 260—280px，右栏约 380—420px，中间使用剩余宽度 |
| 中等窗口 | 优先保证正文和编辑器；空间不足先收起右侧，再进入侧栏抽屉 |
| 手机/很窄窗口 | 单主要视图，侧栏为抽屉，检查面板不与正文硬挤三栏 |
| 更宽窗口 | 中央阅读列限制合理行宽，检查区域可扩展，不把正文拉满整屏 |

断点应依据当前可用空间和各栏最小尺寸计算，不照搬固定值。不支持三栏的宽度下禁止硬凑三栏。

#### B. Token 与排版

- 保留明暗颜色 token，补齐必要的尺寸、间距、圆角、层级与动效 token；避免新组件大量硬编码色值。
- 常规 UI/中文正文用现有系统 UI 字体，代码用等宽字体。不引入字体下载或字体文件。
- 正文、辅助信息和代码各自保持稳定字级；降低元信息存在感时不能牺牲可读性。
- 行高、按钮高度、图标大小和边框风格统一；选择、hover、focus、disabled 区分清楚。
- 长标题使用合理截断和可查看完整内容的入口；长表格和代码内部滚动，不导致整个页面横向溢出。
- 非必要动画遵循减少动态效果偏好；没有任务时保持静止。

#### C. 拖拽与偏好

- 恢复存储宽度时，按当前窗口重新钳制；识别 NaN、异常大值和不合法 JSON，不得恢复后把正文压没。
- 保存显式面板偏好与临时响应式折叠的区别；窗口变窄自动收起，不等于用户永久关闭。
- 拖拽结束保存；取消、失焦、窗口变化时清理拖拽状态。可采用指针捕获，避免鼠标移出后卡住。
- 拖拽只改变尺寸，不重绘正文、不清空输入框，不每次 pointermove 都写持久化存储。
- 保留现有明暗偏好、面板语言/模式和合法宽度。新增配置应有默认值和健壮读取；不要一键清空所有 `localStorage`。
- 控制新增设置数量：本轮只需装饰开关、必要的元信息显示/别名和已有布局设置。不新建庞大的设置中心。

#### D. 浮层、原生桥接与首屏

- 搜索、通知、用户菜单、发送错误、引用卡片、灯箱采用一致的 token 和层级；别只美化主页面。
- 样式严格限定在主题激活范围及被明确接管的组件，不能用裸 `button`、`input`、`dialog` 等选择器污染全站。
- 不删除 Ember/Discourse 正在管理的节点来“清理视觉”；优先采用当前桥接机制，并验证节点归还/销毁路径。
- 不用增加全站深度 MutationObserver 或更高频轮询来解决不同步；保留已有调度去重并尽量增量更新。
- 初次载入可使用有界骨架，不以无限遮罩掩盖初始化失败。数据不可用时显示错误/重试或退回原生。

**验收标准**

不同尺寸、缩放和模式下无全页横向溢出、无重叠点击区域、无不可恢复的隐藏面板。通知/搜索打开关闭正常；窗口从宽到窄再变宽不破坏偏好；站点验证/登录页不受主题污染。

### T10 · 测试、文档和版本交付

- 优先沿用现有测试。没有测试时，只增加必要的纯函数测试和一个离线 DOM/浏览器夹具，不搭建与实际脚本脱节的第二套 UI 实现。
- 高亮、diff、请求归属等测试应覆盖真正被单文件脚本使用的逻辑，不能测试一份手工复制但不参与运行的实现。
- 可以在开发期使用轻量的测试导出/构建手段，但对最终 userscript 保持单文件、无新增运行时外部请求。
- README 仅修改 Codex 相关章节，说明默认减少装饰、右侧来源、原生模式、设置迁移、测试方式与限制。不要改其他皮肤安装链接和说明。
- 遵循当前版本约定更新 `@version`；若已出现更新版本，不能机械覆盖成预设值。保留作者和许可，不添加未经授权的发布地址。
- 提交交付报告，逐项填写第 8 节测试结果和第 11 节完成清单。

**验收标准**：脚本语法检查通过；关键自动化用例有结果；没有环境的项目标为未运行；给出变更文件、安装验证方法、已知限制和回退步骤，而不只是“已优化完成”。

## 6. 最小架构调整建议

本节是组织方式建议，不要求把单文件拆成多个运行时模块，也不要求机械采用下面的函数名。能在原函数内正确修复的部分，应保持小改动。

### 6.1 分清四类数据

| 层次 | 负责内容 | 不能做的事 |
|---|---|---|
| 原始数据 | 站点返回的 topic、post、cooked、分类、链接 | 被显示别名、假活动、面板文件名覆盖 |
| 展示派生 | 标题展示、元信息可见性、分类别名、片段索引 | 写回站点原始模型或发送 payload |
| 交互状态 | 当前路由、选中片段、展开项、编辑草稿、请求状态 | 由无关异步回调或布局刷新任意重置 |
| 本地偏好 | 明暗、合法分栏宽度、装饰开关、有限别名/最近记录 | 存整帖私密内容、CSRF、登录凭据或跨标签全局原生开关 |

推荐把高亮、diff、片段标识、配置校验和展示映射尽量写成可测的小函数。渲染负责展示，桥接负责真实站点操作；不要让别名逻辑进入 API 层。

### 6.2 可选的内部职责划分

```text
shouldBypassTheme()       原生参数、验证页、互斥、未支持路由的优先判断
syncAppChrome()           统一标题、favicon、品牌和当前线程外壳
readPresentationPrefs()   带默认值、类型校验和兼容读取的偏好入口
extractThreadSnippets()   从已加载原帖构建片段，不生成演示数据
renderCodePanel()         保留现有入口，内部按真实/空状态/演示分支处理
teardownTheme()          清理本脚本资源并阻止旧异步任务复活 UI
```

这些名称是建议接口，不能当作基线中已经存在的函数。实现者应优先复用现有同类函数，而不是新旧两套同时存在。

### 6.3 配置兼容原则

现有合法配置继续生效。新配置默认关闭随机装饰，元信息采用弱化展示，真实代码自动优先。演示是用户主动选择的模式，不由“没有代码”自动触发。

配置读取失败只回退对应字段，不清空整个站点存储。需要迁移时做幂等迁移；旧键的清理只涉及本脚本拥有且确实失效的键。设置里的“重置外观”也不能清除站点草稿、登录态或其他主题设置。

## 7. 关键状态的目标行为

| 状态/动作 | 应呈现的结果 | 禁止出现的情况 |
|---|---|---|
| 列表首次加载 | 有界骨架或明确加载提示 | 无限遮罩、原页面永久不可访问 |
| 列表/详情加载失败 | 说明失败、提供重试，必要时提供原生入口 | 同 ID 点击重试直接被缓存判断拦截 |
| 进入有代码的线程 | 可选择已加载片段，来源可追溯 | 显示上一个线程代码或无关随机文件 |
| 已加载内容没有代码 | 简洁空状态/引用附件，允许关闭右侧 | 强制填满假代码或宣称整帖一定无代码 |
| 切换演示模式 | 同一固定场景，演示标识可查 | 假“提交成功”、假命令执行与真实状态混淆 |
| 进入原生模式 | 停止主题接管，保留路径与查询语义 | 新标签页再次变回主题、影响所有标签页 |
| 验证页/其他主题优先 | 让出页面、按现有机制恢复 | 替换验证标题、隐藏挑战按钮、旧请求重建外壳 |
| 编辑时打开/关闭面板 | 保留草稿、光标与编辑器职责 | 全量重绘输入框、吞掉输入法确认 |

## 10. 风险控制与回退

| 风险 | 控制方式 | 验证失败时的处理 |
|---|---|---|
| 原生编辑器被全量重绘破坏 | 编辑区保持稳定节点，只更新必要状态 | 回退相关 DOM 重建，优先保住草稿和发送 |
| 原生模式反复被重新套皮 | 最早阶段旁路 + 标签页语义 + 请求失效 | 保留明确的原生入口，停用主题接管 |
| 高亮覆盖不全 | 正文保真优先，不确定语法转义纯文本 | 降级高亮，不降级内容正确性 |
| diff 统计错位 | 单一 before/after 差异来源和边界测试 | 禁用错误 diff，保留源码片段阅读 |
| 显示别名污染数据 | 独立映射，API/引用只读原始数据 | 关闭别名展示，不修改或“还原”服务器数据 |
| 存储损坏或窗口过窄 | 字段校验、尺寸钳制、临时折叠与用户偏好分离 | 使用安全默认值，不清空全站存储 |
| 依赖站点内部接口发生变化 | 保持既有桥接、限定接管范围、逐项验收 | 允许原生回退，报告受影响功能 |
| 大面积改动难定位 | 分阶段、小而独立的本地提交/补丁 | 只回退本轮对应改动，保留用户其他修改 |

回退说明至少包括：如何停用脚本或进入原生模式、如何恢复修改前的 userscript、如何只重置本脚本新增偏好。不得建议清除整个站点的浏览数据作为默认回退手段。
